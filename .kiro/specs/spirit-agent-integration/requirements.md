# Requirements · 伴生十灵整合与长期记忆
版本0.1 / 2026-10-23；状态Draft。以下SHALL是未来验收目标，不是功能已实现声明。

## 1. 目标、来源和状态
目标：可替换2D灵宠、真实聊天、可靠个人记忆及外部八字上下文能够独立组合。
本轮只整理资料。采用[Kiro Requirements-First](https://kiro.dev/docs/specs/feature-specs/requirements-first/)的需求、设计、任务结构和EARS验收形式。
来源：[原产品边界](../../../source-handoff/docs/01-product-boundaries.md)、[原接口提案](../../../source-handoff/docs/03-agent-memory-bazi.md)、[记忆参考报告](../../../references/learning-agent-memory-design.md)。
[确认]来自本次用户选择；[交接]来自原包传递的决策；[草案/待定]不是用户已确认的实现细节。

## 2. 范围
未来首版：2D小曜、展示解耦、单模型配置、真实对话、生日恢复、独立SQLite、可纠正记忆、迁移与异常处理。
非目标：3D、十灵全套生产、实时生图、语音、收费、桌面常驻、主动监控、跨设备同步、向量库或具外部副作用的工具。
首版沿用本机单用户边界；第二宿主和外部八字组件在资料到位后单独接入，不凭空新增登录。

## 3. 用户故事与验收条件

### R1 保留2D表现 [交接]
作为用户，我希望后端升级不破坏已认可的小曜效果。
1. **R1.1** WHEN 接入聊天或记忆模块，THE SYSTEM SHALL 保留小曜2D造型、暖林栖所及资产状态，不自动改成像素或3D。
2. **R1.2** WHEN 点击、喂食、休息或唤醒，THE SYSTEM SHALL 提供正确表现及文字，不让旧计时器覆盖最新动作。
3. **R1.3** WHILE 启用减少动态效果，THE SYSTEM SHALL 保留操作和文本反馈，不要求动画作为唯一反馈。

### R2 展示解耦 [确认]
作为集成者，我希望换组件不重做数据与模型。
1. **R2.1** WHEN 更换头像或整块灵宠组件，THE SYSTEM SHALL 保留用户资料、配置、记忆与会话归属。
2. **R2.2** WHEN 模型返回表现指令，THE SYSTEM SHALL 校验约定接口与动作白名单，不执行任意脚本或工具。
3. **R2.3** WHEN 卸载展示组件，THE SYSTEM SHALL 清理计时器、监听和动画资源，不影响独立记忆服务。

### R3 可视化模型配置 [确认目标，细节草案]
作为用户，我希望在界面配置并测试模型。
1. **R3.1** WHEN 打开模型设置，THE SYSTEM SHALL 提供地址、模型、密钥输入和配置/测试状态，不回显已存密钥。
2. **R3.2** WHEN 测试配置，THE SYSTEM SHALL 使用草稿验证普通对话与工具能力，明确错误，且不自动保存或写入聊天和记忆。
3. **R3.3** WHEN 保存配置，THE SYSTEM SHALL 由服务端持久化；密钥不得进入前端存储、静态资源、提示词或日志。
4. **R3.4** IF 仅基础聊天可用而工具能力不可用，THEN THE SYSTEM SHALL 标明自动记忆不可用，不混淆能力验收。

### R4 真实对话与失败可见 [确认/交接]
作为用户，我希望辨认真实模型与演示预设。
1. **R4.1** WHEN 展示回复，THE SYSTEM SHALL 区分demo/live，真实请求具有可追踪标识。
2. **R4.2** IF 超时、网络失败或非法回复，THEN THE SYSTEM SHALL 明确失败及重试，保留输入并回到安全表现，不静默冒充真实AI。
3. **R4.3** WHEN 重复提交或迟到响应发生，THE SYSTEM SHALL 避免消息/记忆重复落库及旧结果覆盖新状态。

### R5 保存与恢复 [确认]
作为用户，我不希望反复输入生日或丢失资料。
1. **R5.1** WHEN 保存有效公历生日和时辰，THE SYSTEM SHALL 持久化到当前项目独立SQLite并在后续打开时恢复。
2. **R5.2** IF 日期非法、未来或缺计算信息，THEN THE SYSTEM SHALL 拒绝或列缺项，不悄悄补造。
3. **R5.3** IF 保存失败，THEN THE SYSTEM SHALL 不报告成功，并保留有效旧数据或可重试输入。
4. **R5.4** WHEN 展示或模型变化，THE SYSTEM SHALL 不把生日、角色种类或供应商作为个人记忆归属主键。

### R6 可治理长期记忆 [确认目标；D01/D02/D03待定]
作为用户，我希望被记住，也能知道、纠正和删除内容。
1. **R6.1** WHEN 出现值得长期保留的信息，THE SYSTEM SHALL 按已确认策略写入或提出候选并保存来源，不把模型推测、八字映射直接变成用户事实。
2. **R6.2** WHEN 查看记忆，THE SYSTEM SHALL 提供内容、来源、状态和更新时间，实际提交成功后才能显示“已记住”。
3. **R6.3** WHEN 用户纠正记忆，THE SYSTEM SHALL 按已确认版本策略使旧冲突内容不再作为有效事实召回。
4. **R6.4** WHEN 删除记忆后开启无旧对话的新会话，THE SYSTEM SHALL 不从有效记忆、索引或缓存召回该内容，并说明历史原文和备份保留边界。
5. **R6.5** IF 临时状态纳入首版，THEN THE SYSTEM SHALL 赋予有效期，到期后不视为当前状态或稳定人格。

### R7 有限上下文与降级 [草案]
作为用户，我希望连贯而不无限上传历史。
1. **R7.1** WHEN 组装上下文，THE SYSTEM SHALL 分开近期对话、长期记忆、用户事实及八字解释，并设数量和长度上限。
2. **R7.2** IF 增强记忆读取失败，THEN THE SYSTEM SHALL 按声明策略降级普通聊天，不宣称本轮已成功使用记忆。
3. **R7.3** WHEN 历史内容与当前明确陈述冲突，THE SYSTEM SHALL 优先当前陈述并依纠错策略处理。

### R8 八字适配与来源 [交接；D05待定]
作为用户，我希望使用真实计算结果而非模型编造。
1. **R8.1** WHEN 引入八字结果，THE SYSTEM SHALL 提供引擎/版本、口径、缺项和来源，区分计算、传统解释、创作映射和用户事实。
2. **R8.2** IF 组件或换日等口径未知，THEN THE SYSTEM SHALL 明确partial/unavailable或未接入，不输出确定完整命盘。
3. **R8.3** WHEN 剧情与用户当下自述冲突，THE SYSTEM SHALL 不让预设主题覆盖自述。

### R9 归属与宿主 [确认方向；D04待定]
作为集成者，我希望组件能嵌入其他项目而不误共享资料。
1. **R9.1** WHILE 本机单用户运行，THE SYSTEM SHALL 分离用户身份与展示petId并标明宿主边界。
2. **R9.2** IF 引入多用户或跨项目宿主，THEN THE SYSTEM SHALL 从服务端可信身份构建范围，默认不共享项目私有内容，不相信任意客户端userId。
3. **R9.3** WHEN 仅本机演示得到验证，THE SYSTEM SHALL 不宣称登录隔离、跨设备同步或第二宿主已可用。

### R10 迁移与证据 [确认]
作为接收者，我希望旧数据不误合并且证据可信。
1. **R10.1** WHEN 导入旧数据，THE SYSTEM SHALL 区分bazi-spirit.profile.v1与binghuo-chat-v2的结构、来源和归属，未确认时不自动合并。
2. **R10.2** IF 迁移失败或重复执行，THEN THE SYSTEM SHALL 保留源记录且避免重复，仅成功提交后按约定处理旧副本。
3. **R10.3** WHEN 报告功能验收，THE SYSTEM SHALL 附输入、实际输出、来源和验证方式，不用旧截图、mock或打包检查代替真实功能证据。
4. **R10.4** WHEN 打包本次资料，THE SYSTEM SHALL 原样保留原包，提供完整性清单，不加入密钥、数据库、依赖或私人聊天导出。
