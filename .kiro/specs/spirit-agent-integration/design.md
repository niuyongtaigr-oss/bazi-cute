## 1. 三份上下文的现状
### A. 当前bazi_cute（本机源码核对，未复制宿主代码）
技术栈Node 22+、Express、原生HTML/CSS/JS；已有/api/chat/status和/api/chat文本代理。
配置来自.env/环境变量，没有设置表单或本轮真实模型连接证明。
public/app.js把birth、显式preferences和最近20条成功消息保存到浏览器bazi-spirit.profile.v1。
当前偏好上限600字符，每次请求带角色、偏好及最近9轮+当前消息；后端无数据库或记忆工具循环。
createSpiritProfile返回角色资料；createSpiritView(host,{renderAvatar})返回showIdle/showLoading/show。
其像素效果不是用户交接要求的小曜2D效果，不能作为后者的视觉替代品。
原后端排盘/运势存在此前发现的错误，不应无条件复用为可信适配器。
本包不含这套宿主完整源码；继续开发先取得实际工程，核对版本与启动方式。

### B. 原2D交接包（完整原样附带）
[app.js](../../../source-handoff/app/app.js)中的responseFor是正则/预设回复，不是真实LLM。
localStorage键binghuo-chat-v2，最多40条role/text/mood，与A的role/content结构不同。
已有七状态+blink、栖息地、轻微区域动画、点击/喂食/休息与昼夜；无真正MemoryStore、后端或排盘。
play加gaze类后render重设class的风险仍待复现；本轮没有修复。
历史截图、http-smoke、package-check的原始意义不变，不能代表本次功能重验。
详见[原证据说明](../../../source-handoff/docs/02-current-state-evidence.md)和[素材状态](../../../source-handoff/docs/05-assets.md)。

### C. learning-agent（仅借鉴）

## 2. 已确认、建议与未知
确认：当前只整理资料；后续独立SQLite；密钥服务端；模型按需记忆；展示可替换；完整闭环优先。
交接约束：保留2D小曜与暖林栖所，不回3D，不把未定稿十灵当作完整资产。
未确认：具体REST路径、类别/状态、单条记忆长度、工具回合、超时、版本策略、迁移归属与共享规则。
此前“最近6条/600字符/45秒”等讨论参数是候选，不是用户逐条确认的最终契约。

## 3. 模块与依赖方向
~~~mermaid
flowchart LR
  User[用户] --> UI[宿主界面]
  UI --> View[SpiritView]
  UI --> Host[HostAdapter]
  Host --> Core[AgentCore / ChatProvider]
  Core --> Context[ContextBuilder / MemoryService]
  Context --> DB[(独立SQLite)]
  Core --> Model[服务端模型客户端]
  Core --> Bazi[BaziAdapter]
  Bazi --> External[外部八字组件]
  Core --> Validate[回复和表现校验]
  Validate --> View
~~~
- SpiritView：图像、气泡、白名单动作、交互事件、卸载清理；不读库、不持密钥。
- AgentCore/ChatProvider：会话、模型、记忆操作与来源组织；不访问DOM。
- MemoryService：集中校验、范围、来源、提交、召回、纠错与删除。
- ContextBuilder：有限历史与有效记忆拼装；空段不注入，计数不能代替实际内容。
- BaziAdapter：转换真实组件输出，不让LLM补造历法结果。
- HostAdapter：挂载位置、可信身份和业务范围；不因“预留接口”就新增登录。
- ConfigurationService：单模型设置、测试与密钥管理，独立于聊天记忆。

初期保持一个后端进程，无需为解耦新增微服务、事件总线、插件系统或重换前端框架。

## 6. 记忆、数据流与失败
候选实体：用户资料、会话、消息、长期记忆、来源引用和模型配置。
记忆建议含稳定ID、用户/项目范围、内容、类别、来源、时间和有效状态；版本/有效期依D02/D03决定。
推荐对话流程：
1. 获取可信范围，验证会话与请求幂等标识。
2. 按预算读取近期消息、有效记忆；必要且可用时加入八字上下文。
3. 调模型；校验回复、工具参数和表现白名单。
4. 按D01判定候选/确认，按D03处理重复与矛盾。
5. 在约定事务边界提交消息和记忆，返回真实写入结果与来源。
6. View只接收合法表现；失败明确显示，不冒充live。

“候选”不等于“已记住”。不得仅凭assistant文案认定落库。
工具循环、提交时机和失败重试需在开发前锁定，不照抄learning-agent即时commit到所有路径。
读取增强记忆失败可降级普通聊天，但区别“无记忆”和“服务失败”。
清空或删除期间的旧请求必须被取消或版本拒绝，不能恢复被删内容。
不把当前“仅600字偏好+近期历史”描述成自动长期记忆。

### 删除与历史
清空会话、删除一条长期记忆、忘记生日是不同操作，界面应明确。
删除长期条目不自动删除旧聊天原文或物理备份；跨会话删除验收必须使用无旧对话的新session。
若要对原文/备份一起遗忘，应额外确认范围，不虚称全域删除。

## 7. SQLite与迁移
采用当前项目独立SQLite，不接learning-agent业务库。保持Node宿主，具体驱动随实际工程确认。
数据和主密钥置于静态目录外。必须测试事务失败、关闭重开和数据恢复。
按D06分别处理：
- bazi-spirit.profile.v1：version/birth/preferences/messages，最多20条成功消息。
- binghuo-chat-v2：最多40条role/text/mood，可能有预设欢迎语或规则回复。
不能把历史演示消息标成真实模型，也不能把未确认旧文本自动升级为已确认记忆。
迁移需来源指纹/幂等、事务提交、失败保源、目标存在时不静默覆盖。
